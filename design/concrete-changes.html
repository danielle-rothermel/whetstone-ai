Architectural boundary

Foundation code owns graph binding, provider semantics, failure classification, and the shared Evaluation Role. The canonical evaluation engine owns intent execution and evidence. The runner composes these contracts and publishes projections without redefining them.

Foundation

Native graph identity

Whetstone consumes dr-graph Graph Definitions, Graph Configs, and full Graph Hashes directly. Its node helpers bind provider-call and evaluation-procedure configuration without introducing another identity payload.

Character bounds

A finite positive ratio is graph configuration. The concrete character limit is derived safely from the runtime input length and never overflows through float arithmetic.

Provider semantics

Transport evidence is accepted only when request identity, policy identity, response text, semantic classification, and finite timing agree. Bounded retry and backoff are explicit policy.

Evaluation vocabulary

EvaluationRole is a small shared enum. Richer evaluation context belongs to the canonical evaluation intent and evidence schemas that actually consume it.

Canonical evaluation path

  1. The caller persists an exact Evaluation Intent before spending capacity.
  2. The evaluation service validates candidate, Graph Hash, Eval Config, task plan, role, purpose, and route.
  3. The engine executes through the provider substrate and code-evaluation kernel.
  4. Success or failure produces one content-addressed Evaluation Evidence record sufficient to explain the attempt.
  5. Aggregates resolve the explicit plan and evidence set; absent rows never disappear silently.
  6. The runner re-resolves all canonical references and publishes one atomic viewer projection.
