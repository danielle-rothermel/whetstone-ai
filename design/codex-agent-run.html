Run envelope

The run fixes repository input, base candidate, optimizer configuration, tool configuration, model route, budgets, and evaluation policy. Each agent step and tool call resolves back to this immutable envelope.

Tool state machine

Proposed

The call has parsed arguments and a stable call identity. No capacity has been debited.

Accepted

Generic tool preflight succeeds and the exact evaluation intent is persisted before capacity debit.

Terminal

The call binds success, refusal, or identity-rich failure. Accepted calls cannot disappear into an untyped exception.

Evaluation tool flow

  1. Parse and validate the candidate, Eval Config, task subset, purpose, and role.
  2. Reject malformed or unauthorized requests before paid provider work.
  3. Persist the exact Evaluation Intent and transition the tool call to accepted.
  4. Invoke the canonical evaluation service, including ownership and heartbeat handling.
  5. Bind the resulting success or failure evidence to the accepted call.
  6. Return a typed summary that preserves missing and failed states rather than inventing a numeric score.

Budgets and evidence

Token, call, and spend limits are explicit controls. Spend is attributed from identity-bearing provider evidence, not reconstructed from a shared balance delta. Tool output, agent transcript, candidate edits, and evaluation evidence remain separately addressable and are connected by typed references.

Terminal publication

The runner publishes one immutable viewer projection after validating the final candidate, agent transcript, tool-call states, budget accounting, and canonical evaluation evidence. Publication reports authority already established by evaluation; it never creates it.
