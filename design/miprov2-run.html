Owned state

Bootstrap

Demonstration selection, bootstrap evidence, candidate constraints, and the exact data split are typed MIPROv2 inputs.

Study

Trial identity, parameters, observations, terminal state, and best-trial selection are durable and validated.

Result

The result binds the native request, study transcript, candidate artifacts, evaluation evidence references, and terminal disposition.

Trial sequence

  1. Validate the run envelope, task split, bootstrap inputs, and trial budget.
  2. Persist a typed proposal request before invoking the shared proposal-effect executor.
  3. Parse the returned proposal and bind it to the exact semantic request.
  4. Create an Evaluation Intent for the trial candidate and planned minibatch.
  5. Resolve canonical Evaluation Evidence and record the observation without flattening missing or failed states to zero.
  6. Persist the terminal study state and selected candidate.

Failure behavior

Bootstrap, proposal, and evaluation failures remain distinguishable. A terminal study result explains exhausted budget, refusal, provider failure, evaluation failure, or successful selection. Replay resumes from durable typed state and never reconstructs trial meaning from logs.

Shared boundaries

The proposal-effect executor is algorithm-neutral and shared with COPRO and GEPA. Evaluation runs through the canonical evaluation service. DBOS provides checkpoints, while Whetstone schemas define semantic identity and terminal authority.
