Quick-Test Task Rubric

Choose a small task that exposes optimization signal while exercising canonical evidence end to end.

Required properties

Fast

A complete candidate evaluation finishes quickly enough to repeat during development and code review.

Deterministic scoring

Ground truth and metric extraction are programmatic, exact, and independent of an LLM judge.

Learnable structure

Examples reveal multiple separable rules so prompt changes can produce incremental gains.

Nontrivial failure surface

Wrong outputs diagnose which rule failed; a single aggregate scalar is insufficient.

Contamination resistance

Generated instances and private conventions prevent memorized benchmark answers from dominating.

Bounded cost

Task count, repeats, provider calls, timeouts, and character budgets have small explicit limits.

Contract coverage

  • Uses a native Graph Config and verifies its Graph Hash.
  • Declares an exact ordered task and repeat plan.
  • Exercises both accepted provider output and at least one typed failure.
  • Persists canonical Evaluation Evidence with candidate, Eval Config, role, purpose, route, and row accounting.
  • Builds a Rollout Aggregate from the declared plan rather than observed rows alone.
  • Publishes a viewer projection only after every reference is re-resolved.

Acceptance

CheckPassing evidence
ReproducibilityRepeated fake-transport runs produce the same semantic identities and terminal references.
Failure fidelityMissing, failed, refused, and zero-score cases remain distinguishable.
Optimization signalAt least two deliberate prompt changes create explainable, ordered score differences.
AuthorityInternal evidence cannot be published as official by matching hashes or display labels.
PackagingFocused tests, full tests, Ruff, ty diagnostics, build, and diff checks pass.

Out of scope

The quick test does not establish production throughput, provider exactly-once behavior, long-horizon optimizer quality, or statistical power for final research conclusions. Those require dedicated validation.
