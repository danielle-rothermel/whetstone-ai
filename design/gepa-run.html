Effect protocol

Every GEPA semantic request receives a stable ordinal. Completed effects form one contiguous transcript, and each stored result is revalidated against its request before reuse. This protocol owns GEPA meaning; it does not duplicate physical provider-attempt durability.

Iteration sequence

  1. Select parents and evaluation traces from the validated GEPA state.
  2. Persist the next semantic effect request and ordinal.
  3. Use the shared proposal-effect executor for any provider-backed draft.
  4. Validate transcript, candidate, and required prompt structure.
  5. Evaluate the candidate through an exact Evaluation Intent.
  6. Append the resolved result and evidence references to the contiguous effect transcript.
  7. Update the candidate population and Pareto metadata without assigning official authority.

Recovery invariants

Semantic continuity

Ordinals are unique and contiguous; an existing request can resolve only its exact validated result.

Physical honesty

Provider evidence states provider-idempotent or at-least-once durability and retains the stable physical key.

Evaluation fidelity

Candidate, task plan, role, purpose, route, and step identity survive in canonical success or failure evidence.

Publication

Runner output is an atomic projection over the final GEPA state and re-resolved evaluation evidence.
